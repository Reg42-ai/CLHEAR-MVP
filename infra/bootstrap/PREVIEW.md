# Private hosted CLHEAR preview bootstrap

[clhear-preview.json](clhear-preview.json) is the one-time owner-reviewed CloudFormation setup for a separate presentation preview. It is not applied by the preview workflow. Create it only in account **730649732189**, **us-east-1**, after reviewing a change set with `CAPABILITY_NAMED_IAM`. Outside that account/region the template creates no resources or preview outputs.

The stack creates one Lambda (`clhear-preview-webui`), one HTTP API and its integration, one dedicated Cognito app client and its login style in the existing pool, a generated session-signing secret, one log group, and two scoped IAM roles. By default it also attaches one narrowly scoped managed policy to the **existing `clhear-github-deploy` role** for code-pointer metadata. It creates no database, workers, queues, schedules, or copy of the corpus. It does not modify `clhear-webui` configuration/code, the existing Cognito client, or any accepted-release pointer.

The HTTPS endpoint is reachable over the internet; **private means approved sign-in in CLHEAR**, not VPC-only networking. Anonymous health and sign-in routes remain available. Original texts retain the same source permissions as the worker-produced candidate. Preview mode mounts that snapshot read-only, suppresses database/queue writes including auth-user upserts, and rejects operational actions. All of those protections must already be in the reviewed main ZIP used for bootstrap.

## Before the owner creates the stack

1. Merge the single reviewed PR containing the preview runtime, trusted-main preview workflow, and L0 relay repair; wait for its full CI and initial full deployment. Keep `CLHEAR_FAST_DEPLOY_ENABLED` unset or `false` at this stage so the existing full deployment remains usable before metadata IAM is installed. Choose the complete Lambda ZIP from that reviewed main deployment, never a ZIP assembled from arbitrary branch application code. Confirm its SHA256 against the build receipt and record its S3 key and immutable version. CloudFormation pins the version but does not independently verify the build receipt.
2. Confirm the existing `clhear-deploy-730649732189` bucket has versioning and public-access blocking enabled. The code ZIP and `webui/l1/candidate.db` must exist. Candidate bytes are produced by CLHEAR L0; neither this stack nor preview CI imports or repairs data.
3. Confirm the existing user-pool ID and hosted-login domain refer to the same **us-east-1** pool. Set `CognitoLoginVersion` to that domain's existing branding version: **1** for classic hosted UI or **2** for managed login. The stack attaches a style to the new client only; it does not change the existing domain version or pool tier. Select existing identity-provider names supported by that pool. The default `COGNITO` supports existing local users; include `Google` or existing federated provider names if those are how reviewers authenticate. Do not create alternate user identities to bypass the reviewer allowlist.
4. Set the approved reviewer emails. Each reviewer must authenticate with a verified email matching this list. The parameter is `NoEcho`; do not paste full Lambda configuration or secret values into build logs or review evidence.
5. Use the AWS console's CloudFormation change-set review, select this template, and provide `DeploymentBucket`, `InitialCodeKey`, `InitialCodeVersion`, `CognitoUserPoolId`, `CognitoRegion`, `CognitoDomain`, `CognitoIdentityProviders`, `CognitoLoginVersion`, `ApprovedReviewerEmails`, and an optional existing `PermissionsBoundaryArn`. Leave `IncludeStableCodeMetadataPolicy=true` for this one-time setup unless the standalone role stack already owns the named companion policy. The owner identity needs the corresponding CloudFormation/IAM/Lambda/API Gateway/Cognito-client-and-style/log-group/Secrets Manager creation permissions, permission to attach the metadata policy to the existing deployment role, access to the versioned ZIP, and permission to resolve the new secret. The preview deployment role has none of those provisioning grants.

`InitialCodeKey` accepts a reviewed `webui/deployments/.../webui.zip` or `webui/previews/.../webui.zip`. `InitialCodeVersion` cannot be `null`. The existing bucket and pool remain outside stack ownership. The template adds a client, not a new pool or domain.

The API is created independently of the Lambda. Its endpoint determines the new client's sole callback, `/auth/cognito/callback`, and the Lambda's `CLHEAR_PUBLIC_BASE_URL`. The integration is attached afterward, avoiding an API/client/function dependency cycle. Lambda Function URLs are not used because this account's organization policy blocks that path.

## Connect the trusted preview workflow

The GitHub environment **`clhear-preview`** in `Reg42-ai/CLHEAR-MVP` has already been created with a main-only deployment rule and no second reviewer. The role variable and fast-deployment flag remain disabled until owner bootstrap succeeds. `.github/workflows/deploy-preview.yml` on main is the trusted orchestrator even when it previews branch presentation assets. Keep branch validation, CI checks, repository identity checks, serialized deployment, and the strict presentation-file allowlist in that main workflow. A branch must not supply Python, dependencies, a Dockerfile, deployment logic, workflow logic, or auth settings to the hosted Lambda.

After the owner executes this one change set and the initial preview passes sign-in verification, Codex can read the nonsecret outputs and set these environment variables:

- `CLHEAR_PREVIEW_DEPLOY_ROLE_ARN` = `PreviewDeploymentRoleArn` (`arn:aws:iam::730649732189:role/clhear-github-preview`).
- `CLHEAR_PREVIEW_URL` = `PreviewUrl` (the HTTPS API endpoint).

After verifying `StableViewerMetadataPolicyArn` is attached to `clhear-github-deploy`, set **`CLHEAR_FAST_DEPLOY_ENABLED=true` in `clhear-l1`**. Run the trusted main deployment once to establish the verified code pointer. Missing pointer metadata deliberately selects the full path; it never invents a fast baseline. Subsequent qualified branch previews and owner-merged presentation changes run automatically through their existing workflows. There is no per-iteration infrastructure approval or manual ZIP upload.

The companion `clhear-viewer-code-metadata` policy permits only `GetObject`/AES256 `PutObject` on `deployments/l1/viewer-release.json`, plus `ListBucket` with that **exact prefix**. This makes absent-pointer detection distinguishable from denied access without exposing a general bucket listing. It grants no source-data or accepted-release write. It is a managed policy because the existing role's inline policy is already **10,226 bytes**, leaving only 14 bytes under IAM's 10,240-byte aggregate inline limit. The companion has its own size allowance and leaves existing scoped grants unchanged.

Only one stack may own the named companion policy. The preview stack enables it by default; [clhear-deployment-role.json](clhear-deployment-role.json) mirrors the exact same document with `IncludeStableCodeMetadataPolicy=false` by default. If the standalone stack owns it instead, set this preview parameter to `false`. Do not enable both or try to import an existing IAM policy by recreating its name. The policy is retained on deletion/replacement so retiring a preview cannot silently remove the stable fast-lane permission.

The function name is fixed as `clhear-preview-webui`; `PreviewCognitoClientId` and `PreviewCallbackUrl` are nonsecret setup evidence. No session-secret value belongs in GitHub. The trust is exactly `repo:Reg42-ai/CLHEAR-MVP:environment:clhear-preview` with audience `sts.amazonaws.com`. That environment claim itself does not encode a branch or workflow filename. Main-only environment rules and reviewed workflow code supply those constraints. The preview role's maximum session is one hour.

The preview deployment role can read the verified code pointer `deployments/l1/viewer-release.json`, list only that exact prefix to confirm absence, and read versioned complete main ZIPs, then write encrypted ZIPs only under `webui/previews/`. This includes an immutable `previous-viewer.zip` backup. It can get, update code, and invoke only the **preview Lambda**. It cannot update Lambda configuration/concurrency, change IAM, call ECS/RDS/SQS, or write a candidate/accepted release. It does not directly read corpus objects. Updating preview code nonetheless executes with the preview runtime's read permission, and `GetFunctionConfiguration` includes the preview's separate session key; never log that response.

The runtime role has only `s3:GetObject` on the single candidate object and log-stream writes under `/aws/lambda/clhear-preview-webui`. S3 HEAD uses the same object-read grant. Cognito token exchange and public signing-key verification use HTTPS, not AWS IAM administration APIs. Runtime has no SES, SSM, Secrets Manager, SQS, Aurora, or S3 write permission. CloudFormation resolves the new Secrets Manager secret into the Lambda environment during owner setup. The secret is retained on stack deletion; changing its stored value alone does not update the Lambda environment. Rotation requires an owner-reviewed configuration update and invalidates preview sessions. Stable sessions use a different key.

## Verify and operate

Verify the initial Lambda `CodeSha256` against the reviewed complete ZIP, `Active`/`Successful` state, preview/restricted flags, correct candidate URI, and the absence of a reserved concurrency setting. The template intentionally uses the shared account concurrency pool. It creates no positive reservation.

For the initial bootstrap, the owner warms the preview in the Lambda console with the HTTP API v2 `GET /api/clhear/health` test event used by `scripts/deploy_viewer.py` in `_probe`, and confirms a `200` response. This read request uses the already provisioned preview runtime and does not require a code pointer or GitHub deployment variables. Then verify anonymous private API denial, successful Cognito sign-in for an approved reviewer, and rejection for an unapproved account. After that verification, configure the variables and seed the pointer in the order above. Subsequent presentation updates use the deployment controller's built-in warm-up and access probes. Confirm the viewer identifies a candidate snapshot and that write actions cannot enqueue work. Record hashes, snapshot revision/timestamps, flags and status codes only. Do not retain source text, cookies, OAuth codes, tokens, or Lambda environments as evidence.

The function has 1024 MiB memory, 2048 MiB temporary storage, and a 60-second Lambda timeout, matching the current candidate size. The HTTP integration has AWS's 30-second limit; the controller's direct warm-up invocation should finish before browser verification. A cold browser timeout does not justify disabling restricted access or importing a separate database.

Branch presentation updates affect this single shared preview URL. Stable main remains the acceptance/release path. A preview is not proof of L1 completeness or a successful daily run: it shows the latest snapshot the CLHEAR workers actually published. If L0 publication is blocked, the preview stays on that last published revision and must show its age. Fix data and workflow problems through CLHEAR workers and the normal main process.

To change approved reviewers, authentication, IAM, or snapshot location, use an owner-reviewed stack update; preview CI preserves runtime configuration. To retire the preview, remove its GitHub environment authority and review stack deletion. The separately generated secret and companion metadata policy remain retained for explicit owner cleanup. Before removing the companion policy, disable `CLHEAR_FAST_DEPLOY_ENABLED` or transfer policy ownership through a reviewed procedure. The existing pool, source snapshot, stable viewer runtime, workers, and accepted releases remain outside this stack.
