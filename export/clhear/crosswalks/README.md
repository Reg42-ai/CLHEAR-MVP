# Identifier crosswalks

Licence: CC BY 4.0. Standard §8 (interoperability), HLD v2 §7.3 (rights and sourcing).

A crosswalk says: *this CLHEAR building block (L3) corresponds to that control identifier in a framework a bank already runs*, and *this framework identifier corresponds to that one in another framework*. Crosswalks are **identifier** mappings with a SKOS relation and a stated basis — they are never a substitute for the source text and never carry text from a licensed standard.

| Framework | Key | Reproduced | Rights basis |
|---|---|---|---|
| NIST Cybersecurity Framework 2.0 | `nist/csf-2.0` | identifiers and titles | US Government work — public domain |
| NIST SP 800-53 Rev. 5 | `nist/sp800-53r5` | identifiers and titles | US Government work — public domain |
| ISO/IEC 27001:2022 Annex A | `iso/27001-2022` | **identifiers only** (e.g. `A.5.31`) | licensed; text through the BYOL viewer |
| CSA Cloud Controls Matrix v4 | `csa/ccm-4.0` | **identifiers only** (e.g. `GRC-07`) | CSA terms |

## Files

- `seed.json` — the curated seed: framework registry, public-domain titles, framework↔framework edges (basis: NIST CSF 2.0 informative references / OLIR, CSA's CCM↔CSF mapping), and block↔framework edges from the curated block library.
- `<framework>.json` — per release, the complete crosswalk from every current block to that framework, including edges derived through another framework (`via`). Generated by the release pipeline from `seed.json`, the blocks' own `implements_controls` anchors and the requires edges — every row names its basis.
- `index.json` — the frameworks and row counts in this release.

## Relations

SKOS mapping properties, in the meaning SKOS gives them: `exactMatch` (interchangeable), `closeMatch` (usable as equivalents in most applications), `broadMatch` / `narrowMatch` (one is a superset of the other), `relatedMatch` (associated, not equivalent). A crosswalk derived through another framework (block → CSF → ISO) is degraded one step: `closeMatch` ∘ `closeMatch` → `closeMatch`; anything with a `relatedMatch` in the chain → `relatedMatch`.

## API

`GET /interop/crosswalks` (frameworks), `GET /interop/crosswalks/{framework}` (all rows), `GET /interop/crosswalks/{framework}/{ref}` (blocks for one identifier, with the obligations those blocks are required by), `GET /interop/blocks/{BLK-id}/crosswalk`. The same rows appear as `skos:*Match` properties in the JSON-LD export (`GET /interop/jsonld/{id}`) and as `crosswalk` fields in GraphQL.

## Contributing a mapping

File a contribution of kind `ontology_entry` with `target_ref` = the block id and `proposed` = `{framework, ref, relation, basis}`; two reviewers accept, the next release ships it here with your name.
